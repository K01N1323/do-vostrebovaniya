# Приёмка итерации 0.2 — место смотрителя

Основа: `docs/iteration-02-contract.md`. Проверки этого этапа заменяют ожидания итерации 0.1 о перемещающейся камере, полноэкранном разговоре и мгновенном исчезновении выдаваемого пакета.

## Статус

15 октября 2026 года автоматические проверки итерации 0.2 исполнены на этом Mac в Godot `4.7.2.stable.official.ed1daf0bf`: ядро — 957 проверок, новая сцена и UI — 310 проверок. Оба процесса завершились с кодом 0; итоговые журналы не содержат `ERROR`, `SCRIPT ERROR` или `WARNING`. Графический прогон в Compatibility на Apple M4 сохранил 23 кадра и завершился с кодом 0. Результаты 957/122 из `docs/acceptance.md` относятся к итерации 0.1 и хранятся отдельно.

## Автоматические проверки

`tests/test_runner.gd` сохраняется: прежние правила первого обращения, три решения Нины, знания, отклонение некорректных команд, RESTART и независимость снимков. Новый прогон подтвердил все 957 проверок.

`tests/scene_smoke.gd` проверяет:

| Область | Проверяемое поведение |
| --- | --- |
| Запуск | Меню блокирует комнату. Кнопка начала запускает подготовку, затем START; Нина переходит absent → arriving → waiting. |
| Место игрока | Камера во всех четырёх видах остаётся в публичной `camera.EYE`; меняется только ориентация. Ограниченный поворот головы также сохраняет EYE. |
| Действия | Исходное положение P01 и последующие shelf/desk/personal берутся из `room.PACKAGE_POSITIONS`, без координат из 0.1. |
| Разговор | `_modal_kind == dialogue`; блок расположен внизу, положительного размера, в пределах экрана. Комната и поворот головы остаются доступны; NPC не перекрыт панелью. Начало разговора возвращает взгляд от стола к окну и закрывает крышку в переднем плане, сохраняя знания. Обновления реплик не открывают её повторно. |
| Реплики | Вопрос об обеде доступен после бутербродов. Реплики показываются частями; переход к следующей части меняет текст, завершение не меняет состояние пакета. |
| Бумаги | Удостоверение содержит видимую фотографию. Сравнение отмечает две прочитанные бумаги. Пакет не перемещается. Панель имеет положительный размер, находится внутри viewport, не занимает весь экран и не создаёт непрозрачную подложку на весь экран. 3D-клики и поворот головы заблокированы до закрытия. |
| Осмотр | Ограниченная панель открывает пакет на столе, отдельный 3D-мир осмотра работает, модель вращается, выбор признака записывает знание. Вещи на полке и под столом визуально закрыты. |
| Решение | Ограниченная панель блокирует 3D-клики. Все три кнопки фиксируют прежний результат ядра. Реакция компактна, вид на окно и передачу сохраняется. |
| Защищённая выдача | ISSUE_PACKAGE сразу завершает обращение. Существующий P01 проходит к hatch; выдача завершается максимум за 2 секунды обычной анимации. В каждый проверенный кадр не открыты обе дверцы. После завершения пакет скрыт и не участвует в picking. |
| Повтор снимка | Повторный `apply_snapshot` с тем же issued-состоянием не запускает вторую выдачу и не отправляет повторный `handover_finished`. |
| Загрузка issued | Первое применение уже выданного состояния в новом представлении просто скрывает пакет и не запускает передачу. |
| Уход | После решения Нина остаётся для реакции, затем достигает gone. Логический результат ядра не зависит от прошедшего времени. Промежуточную фазу leaving дополнительно ожидает графический runner. |
| RESTART | Отменяет передачу и движение Нины, возвращает закрытый P01 на полку. Ожидание старой анимации после RESTART не меняет новое состояние. |
| Возврат в меню | Сбрасывает обращение, скрывает Нину, блокирует комнату; новый START запускает чистое обращение. Настройки звука и уменьшенного движения сохраняются в пределах запуска. |
| Настройки | Уменьшенное движение доходит до камеры и комнаты; выключение звука остаётся доступно. |

Проверка шлюза использует публичное состояние дверей, согласованное с агентом помещения. Семплирование по кадрам проверяет наблюдаемые состояния, а не доказывает временной порядок между кадрами. Порог завершения передачи — 2 секунды с допуском 50 мс на планирование процесса.

Повторный запуск из папки проекта:

```sh
./tools/Godot.app/Contents/MacOS/Godot --headless --path . --log-file "$PWD/tools/tests-02.log" --script tests/test_runner.gd
./tools/Godot.app/Contents/MacOS/Godot --headless --path . --log-file "$PWD/tools/scene-smoke-02.log" --script tests/scene_smoke.gd
```

Успех требует строки `PASS`, кода завершения 0 и чистого журнала: ошибки движка иногда не меняют код завершения процесса.

## Кадры и проверка глазами

`tests/visual_preview.gd` исполнил отдельную серию из 23 кадров в `tools/preview-02/`: меню, подготовка, приход, ожидание у окна, разговор и следующая часть реплики, удостоверение с фото, два документа, стол, осмотр, решение, кадры передачи, реакция, уход, хранение, личное место. Он также сохранил `manifest.json` с фазами посетителя, дверями и положением камеры. Графический захват выполняется отдельно от интерактивной проверки активного окна.

Оркестратор просмотрел кадры меню, разговора, одиночного удостоверения, сравнения бумаг, осмотра и передачи. Исправлены слишком резкие пятна материалов, мелкое лицо, ошибочная автоматическая высота реплики и крышка переноски, заслонявшая посетителя после осмотра. Выбранные окончательные кадры сохранены в `docs/screenshots/v0.2/`. Направление графики задано; финальные модели, реакции лиц и анимации рук остаются отдельной работой.

На сохранённых кадрах и в окне нужно проверить:

1. Место игрока читается как защищённое рабочее место от первого лица: стойка, посетитель по другую сторону, полка рядом и предметы на своей стороне.
2. Лицо Нины остаётся видно во время разговора и реакции на выдачу; текст разбит на читаемые порции и не налезает на панель действий. При хранении и присвоении камера может показать итоговое место вещи.
3. Бумаги имеют фактуру и читаемые поля; панели не выходят за экран на размере окна этого Mac.
4. Осмотр показывает три бутерброда и другие признаки, позволяет вращать модель, не теряет состояние после закрытия.
5. Защитная выдача видна из рабочего места: внутренняя дверца закрывается до открытия внешней, пакет не дублируется.
6. Приход, ожидание и уход Нины воспринимаются непрерывно; в меню она не стоит у окна заранее.
7. Переключение видов не переносит игрока по комнате; ПКМ поворачивает голову в ограниченном диапазоне.

Проверки размеров панелей и пересечения с проекцией лица дополняют просмотр кадров. Они сами по себе не подтверждают художественное качество или читаемость шрифта.
